# 跨区域入职材料一次告知系统 — 一页纸需求规格（V0.1）

> 编制视角：企业信息系统架构师（需求评审结论驱动）｜ 适用范围：立项 / 技术评审基线

## 一、背景与目标
新入职员工常因"不知道要交什么材料、反复跑、反复问"影响入职体验并占用 HR 大量答疑精力。本系统面向**集团型、多法人、跨省市分支**企业，在员工入职各关键节点**一次性、主动**告知其所需材料清单，并支撑"提交 → 审核 → 驳回 → 补交"的线上闭环，达成目标：**员工材料零返工、HR 零重复答疑、集团可统一管控**。

## 二、目标用户与角色
- **员工（多端用户）**：查看个性化清单、接收提醒、上传材料、跟踪办理状态。
- **HR / 管理员（管理后台）**：配置区域/岗位规则、审核材料、监控办理进度。
- **集团管理员**：多租户（法人/子公司）隔离策略与统一管控。
- **系统对接方**：HRIS、OA、SSO、电子签、档案系统等集成端点。

## 三、核心功能（MVP 范围）
1. **材料规则引擎**：按【区域 + 岗位 + 用工类型 + 入职节点】动态生成个性化材料清单（可视化配置，免改码新增）。
2. **一次告知与主动推送**：入职事件触发，经消息中心推送至企业微信/钉钉/短信/邮件/待办，含**已读回执**与催办。
3. **提交与审核闭环**：材料上传 → OCR/证照识别 → 审核工作流 → 驳回/补交 → 状态机全程跟踪。
4. **多租户管理**：按法人/子公司数据隔离，支持"集团统一管控 + 子公司自治配置"。
5. **合规与安全**：PII 数据分类分级、加密存储、脱敏展示、细粒度权限、全量审计日志。
6. **多端接入**：Web、移动 App、企业微信/小程序、管理后台（API-first 设计）。
7. **集成层**：SSO 统一认证、HRIS 主数据同步、OA 待办、电子签、档案系统归档。
8. **多语言 / 多时区**：i18n 可插拔（建议先中 + 英），提醒按员工归属地时区调度。

## 四、关键业务流程
员工入职（HRIS 事件触发）→ 规则引擎生成个性化清单 → 消息中心主动推送 → 员工查看/上传 → OCR 识别 → 管理员审核 → 通过归档 / 驳回补交 → 归档至档案系统（全程留痕）。

## 五、非功能需求
- **合规**：满足等保（建议三级）、个人信息保护法、数据分类分级要求。
- **性能**：清单生成 < 2s；推送到达率与回执可追溯；支持集团级并发。
- **可用性**：多租户严格隔离、零泄漏；SSO 单点登录；关键链路可观测。
- **可扩展**：规则与模板可视化配置，新增区域/岗位/材料无需发版。

## 六、架构倾向（基于需求评审结论）
- **形态**：公有云 **多租户 SaaS**（Q10.1）。
- **前端**：多端（Web / App / 企微小程序 / 管理后台），API-first（Q8.2）。
- **后端**：API 网关 + 集成层（ESB/API，对接 HRIS/OA/SSO/电子签/档案，Q5.2）。
- **核心引擎**：规则引擎（动态清单，Q4.2）+ 工作流引擎（审核闭环，Q6.2）+ 消息总线（主动推送，Q3.2）。
- **数据/存储**：对象存储 + OCR 服务 + 多租户数据隔离。
- **安全合规**：加密存储、脱敏、细粒度权限、审计日志子模块（Q7.2）。
- **多语言/时区**：i18n 框架 + 时区感知调度（Q9.2）。

## 七、待确认 / 风险
- **需求张力**：Q1.1（定位国内跨省）与 Q9.2（多语言多时区）并存——建议 i18n 先落地中 + 英、时区按员工归属地计算，避免过度设计；若确无外籍/海外分支，可降级为单语言。
- **私有化预案**：当前选公有云，但若未来出现数据驻留要求，需预留容器化交付与离线能力。
- **对接清单**：具体 HRIS（SAP/用友/金蝶等）、电子签厂商、企微/钉钉环境需进一步调研确认接口与账号体系。
- **强合规范围**：等保级别、是否涉及密评/关基，需合规团队最终确认。
